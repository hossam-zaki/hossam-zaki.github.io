# hossamzaki.com

A small, static personal site. Plain HTML/CSS — no framework, no build step.
One stylesheet themes everything; blog posts are just Markdown files.

## Files

```
index.html          About / home
publications.html   Publications, honors, innovation, press (edit directly)
projects.html       Projects (edit the cards directly in this file)
now.html            "Now" page — what you're focused on (edit directly)
assets/favicon.svg  Site icon (HZ monogram)
assets/og-image.png Social-share preview image (1200x630)
writing.html        Blog index (GENERATED by build.py — don't edit by hand)
build.py            Regenerates the blog from Markdown. Run after adding a post.
assets/style.css    All styling. Edit the :root variables at the top to retheme.
posts/
  posts.json        List of posts (newest shown first automatically)
  *.md              One Markdown file per post (the source you edit)
  *.html            GENERATED static post pages (don't edit by hand)
post.html           Redirect shim for old ?slug= links
CNAME               Custom domain (hossamzaki.com)
.nojekyll           Tells GitHub Pages to serve files as-is
```

## Add a blog post

1. Create `posts/my-post-slug.md` and write the post in Markdown.
   (Don't put the title or date inside the file — those live in `posts.json`.)
2. Add an entry to the array in `posts/posts.json`:

   ```json
   {
     "slug": "my-post-slug",
     "title": "My Post Title",
     "date": "2026-07-01",
     "excerpt": "One-line teaser shown on the writing page."
   }
   ```

   `slug` must match the filename without `.md`. `date` is `YYYY-MM-DD`.
3. Run the builder:

   ```bash
   python3 build.py
   ```

   This regenerates `writing.html` and `posts/<slug>.html` as plain static
   pages (no dependencies, just Python 3). Posts sort newest-first by date.
4. Commit and push.

The Markdown supports headings (`##`, `###`), **bold**, *italic*, links,
`> blockquotes`, `- lists`, and `---` dividers — enough for essays. The
generated `.html` files are committed so the site needs no server or
JavaScript to display posts.

## Edit other pages

About, Publications, and Projects are hand-written HTML. To add a publication,
copy a `<div class="pub">…</div>` block in `publications.html`. To add a project,
copy a `<div class="card">…</div>` block in `projects.html`.

## Set your GitHub & LinkedIn links

The footers (and the About page) contain placeholder links with `USERNAME` in
them. Find-and-replace `https://github.com/USERNAME` and
`https://www.linkedin.com/in/USERNAME` with your real URLs across the `.html`
files and in `build.py` (then re-run `python3 build.py`).

## Add your headshot

The About page expects a photo at `assets/headshot.jpg` (square works best —
it's shown as a circle). The Now page expects one at `assets/now.jpg`. Drop the
files in with those exact names. If a file is missing, the page just hides the
image and everything else still looks fine.

## Change the look

Open `assets/style.css` and edit the variables at the top (`:root`): colors,
content width, accent. Everything updates at once.

## Preview locally

Every page is plain static HTML, so you can just double-click any `.html`
file to open it in a browser. (Optionally, `python3 -m http.server` from this
folder also works if you prefer a local server.)

## Deploy to GitHub Pages + custom domain

1. Create a GitHub repo and push these files to the `main` branch
   (the site files should be at the repo root).
2. Repo **Settings → Pages → Build and deployment**: Source = *Deploy from a
   branch*, Branch = `main`, Folder = `/ (root)`. Save.
3. The `CNAME` file already sets the domain to `hossamzaki.com`. In Settings →
   Pages, confirm the custom domain shows `hossamzaki.com` and enable
   **Enforce HTTPS** once it's available.
4. At your domain registrar, point DNS at GitHub Pages:
   - Four `A` records for the apex `hossamzaki.com`:
     `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`
   - One `AAAA` set (optional, IPv6): `2606:50c0:8000::153`, `2606:50c0:8001::153`,
     `2606:50c0:8002::153`, `2606:50c0:8003::153`
   - A `CNAME` record for `www` → `<your-username>.github.io`
   DNS changes can take up to a few hours to propagate.

That's it. Edit, commit, push — the live site updates automatically.
